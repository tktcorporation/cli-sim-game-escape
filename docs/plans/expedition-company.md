# 遠征団の設計草案

仮称 **遠征団**。モジュール名は `[TBD: src/games/ 配下の識別子]`。

本ファイルは実装前の設計メモである。
Milestone 1 の骨格が入った PR で、残す WHY を `src/games/<識別子>/DESIGN.md` へ移し、このファイルは削除する。

合意したゲーム性だけを固定する。
数値と固有名の詳細は実装前に別途決める。

## 1. 核となる体験

放置すれば強くなる、ではない。

```
放置 → 何かが溜まる
     → 溜まった燃料で楽しい本編を遊ぶ
     → 本編の結果でチームが強くなる
```

プレイヤーの感情の狙いは次の一文に集約する。

「帰ってきたら遠征の燃料が溜まっている。消化したくなる。遊んだ結果、団が一つ強くなる。」

## 2. 三層ループ

| 層 | 役割 | プレイヤーが得ること | 直接やってはいけないこと |
| --- | --- | --- | --- |
| 放置 | 燃料タンク | 出撃するための資源 | 攻撃力、HP、装備本体を直接上げる |
| 本編 | 楽しさの本体 | 判断、発見、緊張 | 視聴するだけの完全フルオートだけにする |
| 成長 | 永続報酬 | 本編の成績からのみ強くなる | ログインや放置時間そのもので戦力を上げる |

強いチームは、燃料の回復効率を上げる、またはより深い本編を開ける。
強さの源泉は本編側に残す。

## 3. 放置が貯めるもの

放置は **プレイする権利** を貯める。戦力そのものは貯めない。
ここでの「燃料」は、次の2種を指す総称である。

合意した燃料の種類:

- **行軍糧**: 出撃に使うスタミナ相当。上限あり。離席中にゆっくり回復する
- **下調べメモ**: 本編中の選択肢を増やす消費アイテム。結論は書かず、判断材料だけを足す

チームが強いほど行軍糧の回復が速くなる、という間接ブーストは許す。
行軍糧そのものが攻撃力になる設計にはしない。

回復速度の式、上限時間、下調べメモの具体効果は `[TBD]`。

## 4. 楽しい本編（C案）

本編は **出撃前の編成** と **ラン中の分岐** を組み合わせる。

### 4.1 出撃前

- 編成を決める
- 役割を決める
- 持参装備を決める

ここが「放置勇者」的な準備の判断になる。

### 4.2 ラン中

短い遠征ランを、行軍糧を消費して開始する。

道中は数ノードの分岐を持つ。

- 戦闘
- 休憩
- 遺物
- 仲間の一時加入

戦闘はオート進行を基本とする。
ただし要所では介入を残す。

- 奥義のタイミング
- 前列の入れ替え
- 撤退判断

ボスでランを締める。
負けても一部は持ち帰れる。
欲張るとロストする、という張力は `[TBD: 持ち帰りルールの詳細]`。

### 4.3 なぜ C案か

- 編成だけの連戦だと、一回性が薄くなりやすい
- 分岐だけのローグライトだと、団の育成感が薄くなりやすい
- 両方を持つと、「準備して出す」快感と「今回きりの判断」が同居する

## 5. チームが強くなる条件

強さの源泉は本編の結果に限定する。

成長の出口として固定する軸:

- 到達深度 → 絆や拠点施設の成長
- 初めて倒した敵種 → 図鑑補正（発見の報酬）
- ラン中に見つけた編成の成功 → 永続の戦術メモ
- 週ボスへの貢献 → 協力報酬（ギルド段階ではギルド経由の分配も可）

「上手く遊んだ人」「深く遊んだ人」が強くなる。
放置時間の長さそのものでは強くならない。

各成長軸の数値曲線は `[TBD]`。
シミュレーターで到達曲線を固定してから実装する（`.claude/rules/game-simulation.md`）。

## 6. ソーシャル

リアルタイム協力は最初に作らない。
非同期の痕跡から載せる。

| 段階 | 仕組み | 体感 |
| --- | --- | --- |
| S0 | ローカル擬似の他団（シード生成） | 世界に他者がいる |
| S1 | 遠征ログの共有コード / URL | 友達とビルドを交換できる |
| S2 | 非同期レイド（累積ダメージ） | 協力してボスを削る |
| S3 | 軽量ギルド（掲示、助力、週間目標） | 所属感 |

ソーシャルも、放置単体では完結させない。
オフライン進行はソロ完結にし、ログイン時の意思決定だけ他者と接続する。

助力やレイド貢献も、本編プレイの結果として扱う。
放置するだけで他人の進行や自分の戦力が進む経路は作らない。

S0 の擬似他団の見せ方、共有コードの形式、レイド頻度は `[TBD]`。

## 7. 点と線

説明でシナジーを喋らず、数値と配置で気付かせる。

配置しやすい点:

- 役割
- 遺物
- 分岐
- 敵の癖
- 他人の痕跡

プレイヤー自身に引かせる線の例:

- 「この遺物は盾役がいると化ける」
- 「この敵の前では後退配置が正解」

下調べメモは、線のヒントを少し増やす燃料にする。
結論（線そのもの）は書かない。

## 8. 既存ゲームとの位置取り

このリポジトリに既にある近い席:

- `cookie` / `starringe`: ソロ放置成長
- `everlight`: サバイブ戦闘と恒久強化
- `rpg`: 手動ダンジョンのリスク判断

遠征団が取る席は、**編成オートバトルの本編** と **燃料型の放置** と **痕跡型ソーシャル** の交差点。

取らない席:

- AFK Journey 型の広大な探索ワールドを TUI で真似ること
- Survivor 本格アクションの新規追加（`everlight` と競合しやすい）
- 装備連打ガチャを主軸にすること（判断が薄くなる）

## 9. 禁止事項

設計が戻らないための固定ルール。

1. 放置報酬に攻撃力、HP、装備本体を入れない
2. 本編をスキップして成長できる手段を作らない
3. 燃料上限を無限にしない
4. 本編を完全フルオート視聴にしない。最低1つは、意味のある介入か事前判断を残す
5. 最初から本格サーバギルドを作らない

## 10. 実装マイルストーン

実装コードの手順書ではない。
合意した積み上げ順の記録。

### Milestone 0: スコープ固定

- 新規ゲームとして追加する。既存 `everlight` / `starringe` の拡張にはしない
- 非目標: ガチャ課金経済、リアルタイム PvP、広大な探索マップ
- 勝利条件: 「短いセッションで編成が楽しく、放置後に燃料が溜まり、遊んだ結果チームが強くなる。他人の痕跡が気になる」

### Milestone 1: ソロ核

- ヒーロー枠、役割、装備スロットの最小セット（具体数は `[TBD]`）
- 行軍糧の回復と消費
- 出撃前編成
- 短いオートバトル遠征（ログと簡易グリッド）
- 本編成績からのみ成長する経路を1本通す
- シミュレーターで到達曲線を固定する

### Milestone 2: 本編の一回性

- ラン中分岐（戦闘 / 休憩 / 遺物 / 一時加入）
- 要所介入（奥義、前列入替、撤退）
- セット効果や役割シナジーを、説明せず数値で匂わせる

### Milestone 3: ソーシャル S0〜S1

- 擬似他団の遠征痕跡
- 助力（1日数回）
- 編成共有コード

### Milestone 4: ソーシャル S2

- 週間ワールドボス（非同期削り）
- 貢献度に応じた報酬
- 止めを刺した名前が残る演出

### Milestone 5: 磨き込み

- 日課の短さ調整
- UI の情報密度
- critique 指標での確認

## 11. 却下した案と理由

| 案 | 却下理由 |
| --- | --- |
| 放置が直接レベルや装備を上げる古典放置 | 本編が回収作業になり、合意した三層と矛盾する |
| A案（分岐ローグ遠征のみ） | 団の育成感が薄い |
| B案（陣形パズル連戦のみ） | 一回性が薄い |
| AFK Journey の探索ワールド再現 | TUI での制作コストが核を食う |
| Survivor 本格アクション新規 | `everlight` と席が被る |
| Mushroom / Capybara 型の連打装備ガチャ主軸 | 判断が薄く、点と線の設計と合いにくい |
